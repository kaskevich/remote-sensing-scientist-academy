## Quality standard

A lesson is complete only when it supports the full progression:

> understanding → decision-making → application → validation → independence → professional evidence

`COMPLETE` means the complete lesson has been read, revised where necessary, technically checked, rendered, tested and reconciled with the curriculum promise matrix. Existing publication is not sufficient evidence for this status.

## Status definitions

- `NOT STARTED` — not yet reviewed under the curriculum-integrity standard
- `AUDITING` — complete lesson and dependencies are being inspected
- `REVISING` — substantive content, practice or integration changes are in progress
- `TESTING` — content work is complete and validation is in progress
- `COMPLETE` — all lesson and matrix checks passed

### Lesson 1.1 — Welcome to Scientific Programming

- **Purpose:** establish scientific programming as an inspectable method governed by scientific judgement, not introduce Python syntax as an end in itself.
- **Existing strengths:** beginner-safe first instruction, prediction before execution, deliberate error, clear Markdown/code distinction and a strong ecological story.
- **Gaps found:** no explicit connection to later lessons; limited comparison of notebook, report and script; clean execution was mentioned but not practised as a formal QA gate; handover evidence was weak.
- **Professional standard applied:** a beginner should be able to choose why a notebook is appropriate, distinguish execution from validity, recover from one syntax error, reproduce the notebook from a clean kernel and explain the record to a colleague.
- **Changes made:** added the four-part learning pathway, method-choice comparison, notebook-state warning, restart-and-Run-All procedure, independent handover test, Project 1 framing, updated starter-notebook prompts, assessment metadata and an improved reproducibility diagram.
- **Integration issue fixed:** enabled GitHub-flavoured Markdown and responsive tables so professional decision and QA tables render semantically across the Academy.
- **Validation:** 38 Module 1 content tests, TypeScript, ESLint, notebook JSON, SVG XML and GitHub Pages export passed. Lesson 1 was inspected at 320 px and desktop width without page overflow or console errors; the static export contains a semantic table after the renderer correction.
- **Matrix contribution:** strengthens notebook workflows, reproducibility, debugging, scientific communication and Portfolio Project 1. It does not claim to close the later environment, README or Git/GitHub gaps.

### Lesson 1.2 — Variables and Scientific Data

- **Existing strengths:** clear introduction to strings, numbers, Booleans and `None`; scientifically cautious wording around undocumented units; good distinction between missing and zero; and an authentic published-plot application.
- **Gaps found:** no explicit dependency path; no compact data contract connecting Python type to meaning, units, provenance and missingness; no realistic identifier-conversion failure; no professional decision about whether an uncertain value may proceed; and the SVG retained an ambiguous Boolean name that implied sampling knowledge.
- **Professional standard applied:** a learner should be able to inspect a Python type, distinguish computational validity from scientific validity, preserve identifier formatting and source precision, document unresolved metadata and decide whether a value is ready, requires review or must stop the workflow.
- **Changes made:** added the four-part learning pathway, a one-value data contract, leading-zero identifier case, float-display caution, ready/review/stop QA decision, stronger guided and independent work, starter-notebook cells, Project 1 framing, assessment metadata and a scientifically accurate diagram label.
- **Validation:** 38 Module 1 content tests plus the shared Markdown-rendering test, TypeScript, focused ESLint, notebook JSON, SVG XML and GitHub Pages export passed. - **Matrix contribution:** strengthens Python foundations, data-quality reasoning, reproducibility, scientific communication and the second checkpoint of Portfolio Project 1. It prepares table schema auditing in Lesson 8 and pandas-aware missingness in Lesson 9 without claiming those later competencies prematurely.

- **Gaps found:** no explicit dependency path; sequence output could be mistaken for meaningful scientific order; no batch contract; `len(plots)` was not explicitly tied to complete inclusion; missing records were discussed but not processed; professional audit counts were incomplete; and later loop/vector equivalence was not required.
- **Professional standard applied:** a learner should be able to define a batch and its population, process each record consistently, distinguish received from used evidence, justify the denominator, verify a small result independently and determine whether output is ready for handover.
- **Changes made:** added the four-part learning pathway, order-provenance caution, batch-processing contract, denominator explanation, diagnostic-versus-handover output distinction, loop/vector equivalence check, missing-value extension, complete audit summary, QA classification, starter-notebook batch cells, stronger assessment metadata, Project 1 framing and denominator/equivalence language in the visual.
- **Validation:** 38 Module 1 content tests plus the shared Markdown-rendering test, TypeScript, focused ESLint, notebook JSON, SVG XML and GitHub Pages export passed. The generated export contains the batch contract, missingness extension, equivalence check and handover decision.
- **Matrix contribution:** strengthens iteration, batch QA, missingness accounting, reproducibility, validation reasoning and the fifth checkpoint of Portfolio Project 1. It gives Lesson 7 and Lesson 10 a concrete equivalence obligation and prepares Module 2 file/window processing without yet claiming scalable array or geospatial execution.

- **Changes made:** added the four-part learning pathway, function-contract table, five assertions, regression-testing explanation, explicit malformed-record policy choice, non-mutation verification, representation-scope QA classification, starter-notebook function/test cells, stronger assessment metadata, Project 1 framing and regression guidance in the debug visual.

### Lesson 1.7 — NumPy and Numerical Arrays

- **Purpose:** teach arrays as structured, contract-governed numerical evidence and establish the conceptual bridge from a table column to a raster grid.
- **Existing strengths:** authentic published first-row sequences, exact shape and dtype explanation, sound positional-mask teaching, appropriate missingness caution, substantial dataset context and the required concise two-dimensional bridge.
- **Gaps found:** no explicit dependency path; provenance and structure expectations were not consolidated into an array contract; Lesson 5's promised loop/vector equivalence was not executed; masks had no assertions; `np.nanmean` did not require explicit counts or teach `np.isnan`; and the grid discussion did not warn that row orientation is not automatically geographic.
- **Professional standard applied:** a learner should be able to document source, field, scope, order, shape, dtype and missingness; validate structural and positional invariants; reproduce a known loop result; report denominators; and distinguish array coordinates from geospatial coordinates.
- **Changes made:** added the four-part learning pathway, array-contract table, shape/mask assertions, loop-equivalence exercise, explicit `np.isnan` counts and comparison warning, grid-orientation caution, evidence-led QA classification, starter-notebook array/missing/grid cells, stronger assessment metadata, Project 1 framing and selection/validation language in the mask visual.
- **Validation:** 38 Module 1 content tests plus the shared Markdown-rendering test, TypeScript, focused ESLint, notebook JSON, SVG XML and GitHub Pages export passed. The generated export contains the array contract, equivalence task, missingness method and spatial-meaning boundary.
- **Matrix contribution:** strengthens NumPy, array validation, missingness accounting, reproducibility, raster-readiness and the seventh checkpoint of Portfolio Project 1. It supplies a credible bridge to Module 2 raster science while explicitly withholding geospatial claims until transform, extent, resolution, NoData, orientation and CRS are introduced.
